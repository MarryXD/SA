Что такое требования и какие бывают виды
=
**Требования** — это основа любого IT-проекта. Именно на основе требований строится архитектура системы, планируется работа команды и оценивается успешность реализации решения. От того, насколько чётко и полно они сформулированы, зависит судьба всего проекта.

Требование — это условие или ограничение, которое должно быть выполнено для достижения цели проекта. Оно описывает, что система должна делать и при каких условиях она будет работать.

>Проще говоря, требование — это ответ на вопрос: «Что мы делаем и зачем?»

Виды требований
=
Существует несколько уровней и типов требований. Вот основные из них:

**1. Бизнес-требования (Business Requirements)**

Это самые высокоуровневые требования, которые описывают цель проекта с точки зрения бизнеса.

Зачем нужны:
- Чтобы понять, почему проект запущен
- Чтобы определить, что нужно компании или заказчику
  
Примеры:

«Увеличить конверсию на сайте на 20%»

«Сократить время обработки заявок с 48 до 6 часов»

«Перевести клиентскую часть на российское ПО»

**2. Пользовательские требования (User Requirements)**

Эти требования описывают потребности конечных пользователей. Они показывают, что хочет пользователь и как он взаимодействует с продуктом.

Зачем нужны:
- Чтобы понять, как люди будут использовать систему
- Чтобы сделать интерфейс удобным и логичным
  
Примеры:

«Пользователь должен иметь возможность находить нужный товар»

«Менеджер должен получать уведомления о новых обращениях клиентов»

**3. Функциональные требования (Functional Requirements)**
   
Это конкретные функции системы, то есть то, что система должна уметь делать.

Зачем нужны:

- Чтобы разработчики понимали, какие задачи реализовывать
- Чтобы QA мог проверить корректность работы

Примеры:

«Система должна позволять пользователю регистрироваться через email»

«Администратор может просматривать список пользователей и фильтровать его»

**4. Нефункциональные требования (Non-functional Requirements)**

Эти требования описывают характеристики системы : её производительность, безопасность, масштабируемость и другие параметры.

Зачем нужны:

- Чтобы система была не только функциональной, но и надёжной
- Чтобы соответствовать стандартам и ожиданиям пользователей

Основные категории:


| Категория         | Описание            | Пример                                                |
| :-------------    |:------------------  | :-----                                                |
| Производительность| Скорость работы     | Обработка 1000 запросов в секунду                     |
| Надёжность        | Безотказная работа  |   Время безотказной работы — 99.9%                    |
| Безопасность      | Защита данных       |    Все данные шифруются при передаче                  |
| Масштабируемость  | Возможность роста   | Поддержка 1 млн пользователей                         |
| Используемость    | Удобство интерфейса |   90% пользователей находят нужную функцию за 3 клика |
| Поддерживаемость  | Легкость обновления |    Изменения в логике без перезагрузки                |

## Пример иерархии требований:

**Бизнес-требование:**

«Хочу увеличить количество покупок на сайте»

**Пользовательское требование:**

«Пользователь должен быстро находить нужный товар»

**Функциональное требование:**

«Сайт должен поддерживать поиск по сайту»

**Нефункциональное требование / атрибут качества:**

«Поиск должен работать за 0.5 секунды»

**Бизнес-правило:**

«Если товар закончился — показывать “заказать у поставщика”»

**Ограничение:**

«Интерфейс должен быть адаптирован под мобильные устройства»
