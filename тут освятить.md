Основные технические навыки системного аналитика
1. Понимание работы API
API (Application Programming Interface) — это способ взаимодействия между системами.

Зачем SA:
Чтобы описать, как будет происходить обмен данными
Чтобы понять ограничения и возможности системы
Чтобы выбрать подходящий протокол
Что нужно знать:
REST API: методы (GET, POST, PUT, DELETE), коды ответов (200, 404, 500), форматы (JSON, XML)
GraphQL: запросы, мутации, преимущества перед REST
gRPC: использование Protobuf, двусторонний стриминг
JSON-RPC / XML-RPC: простые RPC-протоколы
2. Работа с базами данных (БД)
Системный аналитик часто работает с задачами, связанными с хранением и обработкой данных.

Зачем SA:
Чтобы понимать, где и как данные будут храниться
Чтобы описать логику работы с данными
Чтобы участвовать в проектировании таблиц, индексов, триггеров
Что нужно знать:
SQL: основы языка, запросы SELECT, JOIN, WHERE, GROUP BY
Реляционные БД: PostgreSQL, MySQL, Oracle
NoSQL БД: MongoDB (документная), Redis (ключ-значение), ElasticSearch (поисковая), Cassandra
ER-диаграммы: моделирование структуры БД
3. Понимание архитектурных подходов
SA часто участвует в обсуждении архитектуры решения.

Зачем SA:
Чтобы видеть, как системы взаимодействуют между собой
Чтобы принимать участие в выборе правильной архитектуры
Чтобы понимать риски и сложности реализации
Что нужно знать:
Монолит vs микросервисы
Event-driven архитектура
Layered architecture (слои приложения)
C4 Model: описание архитектуры на разных уровнях детализации
4. Навыки моделирования процессов
Умение создавать диаграммы позволяет наглядно представить процессы, логику работы системы и взаимодействие компонентов.

Зачем SA:
Чтобы показать бизнесу, как будет работать система
Чтобы разработчики могли понять логику
Чтобы фиксировать процессы в документации
Что нужно знать:
UML: use case, activity, sequence, class diagrams
BPMN: описание бизнес-процессов
PlantUML: текстовое моделирование диаграмм
Draw.io / Lucidchart / StarUML: инструменты для создания диаграмм
5. Знание протоколов обмена данными
Современные системы активно обмениваются данными внутри и вне компании.

Зачем SA:
Чтобы выбрать оптимальный способ обмена данными
Чтобы понимать, как работает очередь сообщений
Чтобы описать интеграции правильно
Что нужно знать:
HTTP/HTTPS, TCP/IP
REST, SOAP, gRPC, GraphQL
Kafka, RabbitMQ, ActiveMQ
Webhooks, WebSockets
6. Работа с документацией и спецификациями
Один из ключевых продуктов SA — это документация.

Зачем SA:
Чтобы зафиксировать требования
Чтобы дать команде понятную информацию
Чтобы сохранить историю изменений
Что нужно знать:
Форматы: Markdown, HTML, Word, Confluence
Инструменты: Swagger/OpenAPI, Postman, Redoc, Jira, Notion
Стандарты написания TЗ
Принципы DRY, KISS и другие подходы к документированию
7. Базовое понимание DevOps и CI/CD
Хотя SA не пишет код, он должен понимать, как система будет разворачиваться и поддерживаться.

Зачем SA:
Чтобы учитывать особенности развёртывания
Чтобы описать требования к среде
Чтобы понимать жизненный цикл продукта
Что нужно знать:
Docker, Kubernetes
CI/CD: Jenkins, GitLab CI, GitHub Actions
Жизненный цикл разработки ПО (SDLC)
8. Понимание тестирования
SA может не писать тесты, но обязан понимать, как проверяется реализация.

Зачем SA:
Чтобы помочь QA составить тест-кейсы
Чтобы проверить соответствие реализации требованиям
Чтобы понимать, какие тесты нужны на каждом этапе
Что нужно знать:
Виды тестирования: unit, integration, acceptance, regression
Автоматизация: Selenium, Postman Tests, JMeter
Подготовка тестовых данных

Методологические навыки:

Написание TЗ по стандартам
Использование методологий Agile, Scrum, Waterfall

2. Моделирование и проектирование процессов и систем

основы анализа и моделирования процессов и систем;

иерархию моделей, методы выявления, анализа и документирования состояния системы As Is и To Be;

моделирование процессов с помощью блок-схем;

описание процессов и системы в нотации UML: диаграммы состояний, последовательностей, классов, активностей и вариантов использования;

особенности реализации web-, desktop- и мобильных приложений, кроссплатформенной разработки.

Что хорошо бы знать:

моделирование бизнес-процессов в нотации BPMN (Business Process Model and Notation);

расширенные знания нотации BPMN и UML;

другие нотации, стандарты и фреймворки: IDEF0, IDEF3, EPC, DMN, VAD, SIPOC, BABOK и т. п.;

применение диаграмм компонентов (component) и развертывания (deployment).

3. Работа с базами данных

К этому блоку знаний относятся:

основные типы баз данных — реляционные, объектно-реляционные, нереляционные, колоночные, текстовые, а также популярные системы управления базами данных (СУБД) для каждого типа;

структурированные, неструктурированные и слабоструктурированные данные;

языки запросов — SQL;

теория проектирования реляционных баз данных;

правила проектирования нереляционных баз данных;

для уровня Senior и выше — объектно-реляционное отображение (Object-Relational Mapping, ORM);

подходы к миграции данных — «извлечение, преобразование, загрузка» (Extract, Transform, Load, ETL);

витрины данных, OLAP-системы, проектирование хранилищ данных, витрин данных и отчетных форм.

4. Архитектура

Что нужно знать:

основные виды архитектур и их особенности: локальная, монолитная, клиент/сервер/база данных, сервис-ориентированная и микросервисная архитектура;

архитектурные шаблоны: клиент-серверный, многоуровневый, шаблон посредника, шаблон Model–View–Controller;

паттерны «хореография» и «оркестрация»;

теорему CAP, она же теорема Брюера;

для уровня Senior и выше — событийно-ориентированную (event-driven) архитектуру, включая event sourcing и Command Query Responsibility Segregation (CQRS);

модель Component-Connector-Container и подход С4 Саймона Брауна;

базовые фреймворки для описания архитектуры ПО: 4+1 и, опционально, TOGAF;

основы построения корпоративной архитектуры в Archimate.
Различать синхронные и асинхронные запросы, развивать навыки проектирования для выделения микросервисов, обладать достаточными знаниями для чтения архитектурных схем для последующей спецификации решения.

5. Интеграции

В этот блок знаний входят:

виды интеграций информационных систем: API, шина данных — ESB/MOM/MQ, общая база данных, файловый обмен;

pull- и push-модели;

веб-сервисы и вебхуки;

синхронные и асинхронные взаимодействия;

протоколы и интерфейсы интеграции систем: SOAP, JSON:API, GraphQL, gRPC, а также API нативных библиотек, которые часто используются при интеграции с программными библиотеками или сервисами, которые работают локально, а не через сеть;

общее представление о форматах данных и способах их описания: JSON, YAML, WSDL, XML, XSD и прочие;

основы синтаксиса JSON и XML;

протокол HTTP;

средства документирования и тестирования API: Postman, Swagger, SoapUI, cURL, а также популярные облачные платформы для управления API, таких как Apigee;

принципы REST-архитектуры и REST API;

диаграммы потоков данных (Data Flow Diagram, DFD), которые могут быть дополнены диаграммами последовательности (Sequence Diagrams), для более детального представления потоков данных в синхронных и асинхронных взаимодействиях.

При проработке интеграции необходимо показать, как архитектурные компоненты взаимодействуют между собой, в том числе какие типы данных передаются и какие протоколы интеграции при этом используются. Вопросы интеграции также пора начинать изучать уже Junior-специалистам, накапливая практический опыт и навыки на Middle-уровне. А Senior-аналитики должны спокойно ориентироваться в теме и понимать, в каком случае какая интеграция нужна, а также учитывать при этом различные функциональные требования заказчика, которые могут оказывать существенное влияние на принимаемые решения.
