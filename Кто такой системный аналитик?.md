Чем занимается системный аналитик?
=
**Системный аналитик** — специалист, который работает с IT-системами. Он переводит требования к IT-продукту с языка бизнеса на язык разработки и контролирует процесс его создания — вплоть до запуска в работу. 

Изначально цель бизнеса - это получение прибыли. Сооттветственно цель системного аналитика - это повышение прибыльности бизнеса с помощью решения его проблем или реализации его потребностей.

Задачи системного аналитика (упрощённо):
1. Выявить проблему
2. Найти решение
3. Описать решение
4. Внедрить решение

Работа системного аналитика охватывает множество задач на разных этапах проекта. Вот основные из них:

1. Сбор и анализ требований
- Проведение интервью с заказчиками и конечными пользователями
- Составление user stories, use cases, сценариев использования
- Формализация функциональных и нефункциональных требований
2. Документирование
- Создание технических заданий (ТЗ)
- Описание процессов с помощью диаграмм (UML, BPMN, C4 и др.)
- Поддержка актуальности документации на всех этапах разработки
3. Проектирование интеграций и архитектур
- Анализ взаимодействия между системами
- Выбор технологии обмена данными (REST API, gRPC, GraphQL, Kafka и т.д.)
- Проектирование структуры данных и логики взаимодействия
4. Взаимодействие с командой
- Работа с product owner / менеджером продукта
- Участие в планировании спринтов
- Объяснение техническим специалистам, что нужно реализовать и почему
5. Подготовка тест-кейсов и проверка результата
- Участие в тестировании (Наблюдение за тестированием, оказание консультационной помощи QA при необходимости, редко написание самих тест-кейсов)
- Проверка, что готовый продукт соответствует исходным требованиям

Как SA участвует на разных этапах проекта
=
| Этап проекта    | Роль SA                                                                     |
|:-------------   |:---------------------------------------------------------------------------|
| Инициация       | Выявление потребностей, определение целей, сбор первичных требований        |
| Планирование    | Формализация задач, участие в планировании спринтов, подготовка TЗ          | 
| Проектирование  | Проектирование интеграций, процессов, архитектурных решений                 | 
| Реализация      | Ответы на вопросы разработчиков, уточнение деталей, контроль соответствия   | 
| Тестирование    | Поддержка QA, уточнение критериев приемки                                   | 
| Приемка и запуск| Демонстрация решения, сравнение с исходными требованиями, финальная проверка| 

Обязанности SA:
=
- Анализ бизнес-потребностей заказчика;
- Сбор требований к будущему продукту;
- Анализ требований;
- Анализ проблемных областей и предложения для улучшения;
- Формализация требований;
- Управление требованиями;
- Внедрения требований
